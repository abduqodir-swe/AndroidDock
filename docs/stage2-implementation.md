# Этап 2: рабочие решения реализации

Дата: 2026-10-09. Это технические решения текущей реализации, не перенос всех
рекомендаций PLAN.md в подтверждённые продуктовые требования.

- Сохранены :app и чистый Kotlin/JVM :core:model, оба хоста и один DockScreen.
  ClockStateHolder владеет своим скоупом; Activity использует тонкую ViewModel.
  Редактор хранит обратимый черновик в обычном Kotlin holder, ViewModel переживает
  поворот. Несохранённый черновик не обещает восстановления после гибели процесса.
- AppContainer создаётся Application вручную. Один Preferences DataStore на
  процесс, атомарный JSON конфигурации через kotlinx.serialization. В каждой
  конфигурации две независимые пары раскладок (режим × ориентация); настройки
  часов, фона и комфорта общие для двух ориентаций внутри режима.
- У локальных настроек schemaVersion=1, проверка диапазонов и дефолты для новых
  отсутствующих полей. Неизвестная версия/повреждение дают явную ошибку без
  перезаписи. Это **не формат Dock Packs**; импорт/экспорт не реализуется.
- Редактор применяет изменения только по «Сохранить». «Отмена» и Back возвращают
  сохранённый экран, Undo хранит до 50 операций. Предпросмотр обеих ориентаций,
  Duo/Solo, состав, перестановка, доля первой панели 30–70%, отступы 0–32 dp,
  цвет, размер текста, подложка и скругления доступны локально.
- Начальный режим — рабочий стол: цифровые часы 24 ч с секундами, календарь
  с понедельника, чёрный фон, системная яркость. Спальня — янтарный цвет,
  без секунд/анимации, ночная яркость 8%. Это изменяемые стартовые значения,
  а не окончательный дизайн-контракт владельца.
- Ночь включается вручную в настройках режима. Расписания и датчик освещения
  не реализуются. Яркость через Window.attributes; системная настройка яркости
  не меняется, разрешение WRITE_SETTINGS не нужно.
- Pixel-shift в DockScreen: девять позиций, раз в минуту, максимум ±2 физических
  пикселя. Работает независимо от анимации часов; предпросмотр редактора неподвижен.
  Анимация Flip также учитывает системное отключение аниматоров. Это снижение
  риска, не гарантия отсутствия выгорания и не замена длительных измерений.
- Фото выбирается системным Photo Picker; нет доступа ко всей галерее. Выбранное
  изображение копируется приватно, ограничение входа 32 МБ, декодирование с
  уменьшением до 2048 px, EXIF-ориентация, JPEG. Отображается с затемнением для
  читаемости. Никаких аккаунтов, сети, событий календаря и новых разрешений.
- Батарея — защищённый sticky ACTION_BATTERY_CHANGED, Flow<Availability<T>>,
  отписка при отсутствии наблюдателей. Зарядка включает статусы Charging и Full.
  Температура/ток/ЦП/ОЗУ не добавляются.
- DreamService остаётся неинтерактивным: касание завершает заставку. Редактирование
  и перелистывание месяцев доступны в Activity, Dream показывает текущий месяц.
  Saved-state owner обеспечивает Compose; постоянные настройки читает DataStore.
- Версии прежних зависимостей и SDK 26/36 сохранены. Добавлены DataStore 1.2.1 и
  kotlinx.serialization 1.11.0, проверенные по официальным источникам:
  [DataStore](https://developer.android.com/jetpack/androidx/releases/datastore),
  [serialization](https://github.com/Kotlin/kotlinx.serialization/releases/tag/v1.11.0),
  [Photo Picker](https://developer.android.com/training/data-storage/shared/photo-picker).
  Room, DI-фреймворки, Coil, screenshot-фреймворки, CI и функции этапов 4–5 не добавлены.
- Очистка неиспользуемых фотографий получает список имён **до** закрытия редактора;
  отложенное удаление не может затронуть новую фотографию следующего черновика.
  Временные исходники удаляются импортом в finally; неизвестные файлы не удаляются.
- Настройки заставки открываются с CLEAR_TOP из-за наблюдаемого повторного
  использования старого окна Settings в HyperOS. Флаг не меняет правила запуска
  DreamService и не обходит известное ограничение автозаставки.
- В версии 0.1.1 оба хоста скрывают системные панели через immersive mode.
  Панели можно временно раскрыть системным свайпом; в редакторе Activity они
  возвращаются. При восстановлении фокуса окна применяется режим текущего экрана.
- В Activity меню изначально скрыто. Касание раскрывает/скрывает его, долгое
  нажатие открывает редактор; есть соответствующие действия доступности.
  Постоянная кнопка «Управление» и резерв места под скрытое меню удалены.
  Back сначала закрывает открытое меню; выход из редактора возвращает чистый показ.
  Пользовательский сценарий описан в [usage.md](usage.md).

Аппаратные результаты и отсутствующие проверки записаны в
[platform-findings](platform-findings.md#этап-2--poco-x7-pro-2026-10-09).

## Независимый автопоказ 0.2.0

- Добавлены ChargingWatchService (specialUse), неэкспортируемый DockActivity и
  AutomaticSettingsActivity; DreamService и общий DockScreen сохранены.
- AutomaticStore использует тот же Preferences DataStore: согласие отдельным
  флагом, снимок цикла с boot count отдельно от JSON раскладок. Сериализуемые
  модели и ChargingStateHolder находятся в существующем :core:model.
- Доменный holder получает монотонное время от хоста. Задержка старта 700 мс,
  стабилизация отключения 1500 мс, подтверждение фокуса окна 5000 мс. Повторные
  события не переносят дедлайн; отмена, ручное подавление и восстановление
  проверяются JVM-тестами. Конфигурационный поворот не является ручным выходом.
- Все события службы сериализуются одним Channel; снимок DataStore сохраняется
  до запуска/закрытия окна. AppContainer держит только мост состояния окна.
  Старый токен Activity не может завершить новую сессию после переподключения.
- В API 27+ используются setShowWhenLocked/setTurnScreenOn; API 26 получает
  совместимые флаги окна. Ни dismissKeyguard, ни отключение защиты не используются.
  В DockActivity отсутствуют редактор/переходы; его task отделён от MainActivity.
- Нет старта FGS из POWER_CONNECTED, постоянного оверлея, root, AccessibilityService
  или full-screen intent. SYSTEM_ALERT_WINDOW служит исключением для BAL.
  Начальный старт FGS — из видимой Activity; boot/update имеют отдельное
  документированное исключение. Sticky-перезапуск выполняет ОС.
- Наблюдение — защищённые broadcasts, публичный AppOps listener отзыва overlay
  (включая отключённое питание) + резервная проверка разрешения каждые 3 с
  только на подключённом питании. CPU wake lock ограничен 10 с и удерживается
  лишь во время отложенного запуска/подтверждения окна. На отключённом питании
  после стабилизации нет периодического опроса. KEEP_SCREEN_ON действует в окне.
- Отключение сначала записывает согласие false, затем останавливает службу.
  BOOT_COMPLETED/MY_PACKAGE_REPLACED проверяют сохранённое согласие; receiver
  не работает до первого разблокирования после загрузки и не обходит force-stop.
- Настройки показывают только публично проверяемые Android-разрешения как
  подтверждённые; OEM-состояния неизвестны. Переходы имеют системный fallback.

## Исправление циклов 0.2.1

Продуктовое требование 0.2.0 о подавлении до переподключения отменено.
ChargingStateHolder различает USER_EXIT, DISPLAY_OFF, PERMISSION, LAUNCH_ERROR,
RECOVERY и MODE_DISABLED. Временная пауза ждёт использования телефона,
после которого следующая блокировка разрешает новый показ на том же питании.
Переходы описаны до реализации в [standby-cycle-021](standby-cycle-021.md).

onStop и потеря фокуса не выражают намерение пользователя. Back передаёт Exit,
Home передаёт UserLeaveHint после подтверждённого фокуса. На HyperOS собственное
пробуждение может вызвать ранний hint: в LAUNCHING он игнорируется. SCREEN_OFF
после включённого показа ставит DISPLAY_OFF; экран не будится таймером или
повторными broadcasts. SCREEN_ON от turnScreenOn не считается использованием.
Все события окна имеют уникальный token; старое окно не подавляет новую сессию.
При повороте turnScreenOn повторно не вызывается. Старый suppressed=true
мигрирует в RECOVERY с явным условием снятия — использование/новое питание.
Явное включение после отказа очищает старую паузу, не затрагивая раскладки.

Стабилизация отключения 1500 мс из 0.2.0 больше не используется: потеря питания
закрывает показ/отменяет pending, а следующее подключение начинает новый цикл.
Временная пауза не переносится из снимка отключённого телефона на новое питание.

## Always On 0.3.0

AutomaticStore сохраняет automatic_always_on независимо от automatic_on_power;
старые установки получают false. Наблюдение нужно при логическом OR этих
флагов. MainActivity/настройки/boot/update используют общее consent(), поэтому
восстановление доступно и при Always On без режима зарядки. modeChanges
с distinctUntilChanged передаёт смену политики в тот же последовательный Channel.

ChargingEnvironment получает alwaysOn. Условие питания — plugged || alwaysOn;
подключение/отключение при Always On не закрывает окно и не сбрасывает паузу
DISPLAY_OFF. Выключение Always On без питания закрывает показ/отменяет pending;
при включённом режиме зарядки наблюдение ждёт подключения. Оба false
останавливают службу, а действие уведомления атомарно записывает оба false.
Snapshot/токены и защита собственного turnScreenOn из 0.2.1 сохранены.
Новых Android-разрешений нет. CPU wake lock остаётся коротким и только при
запуске; экран удерживает обычное окно приложения, не системный low-power AOD.
[Переходы](always-on-mode.md), [инструкция](usage.md).
