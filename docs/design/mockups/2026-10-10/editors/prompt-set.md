Controls beyond viewport must scroll while footer remains fixed in implementation.

## QA and limits

All three local PNGs were opened using view_image. Each board shows complete portrait and landscape screen concepts with visible save/cancel controls, Russian labels, dark graphite surfaces and amber selection. Clock includes three actual style thumbnails, scale, color and switches. Calendar includes month grid, week-start controls, today highlight, text scale and weekend color; no events/agenda. Background includes gallery selection, crop frame and dimming, with separately identified app background and system lock-screen wallpaper actions.

The lock-screen button is a system handoff concept. PM checked official WallpaperManager documentation: crop/set intent opens system wallpaper UI and FLAG_LOCK denotes a separate target. Actual HyperOS/OEM availability and choice UI remain unverified and deferred. The boards deliberately do not depict a system page, successful installation, or transferring AndroidDock clock/calendar widgets into the OS wallpaper. Only the source image should be passed; the OS owns the lock-screen clock.

Raster generation introduced small visual-system variations: clock has filled segmented tabs, calendar has an enclosing segmented outline, background has text tabs with indicator. These are concepts rather than final UI specifications. Canonical implementation should use the clock board segmented tabs; the background action semantics remain as depicted. Calendar mode selection was corrected in the bounded review edit below.

No browser, app runtime, ADB, build, automated accessibility, or device test was performed. Static raster inspection cannot validate touch targets, scrolling, dynamic type, contrast ratios, system integration, or actual behavior. No product code, commit, or push.
