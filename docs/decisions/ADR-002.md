# ADR-002: минимальная и целевая версии Android

Дата: 2026-10-09. Статус: черновик, предложение; окончательное решение за владельцем.

## Контекст

Для этапа 0 владелец согласовал временные minSdk 26, compileSdk 36 и targetSdk 36.
Это параметры сборки прототипа, а не обещание поддержки всех устройств начиная
с Android 8.0. Аппаратный прогон выполнен только на POCO X7 Pro / Android 16.
Подтверждённый стек описан в [ADR-001](ADR-001.md), результаты — в
[platform-findings.md](../platform-findings.md).

## Предложение

- **minSdk 26 (Android 8.0)** — сохранить как кандидат. Он позволяет использовать
  java.time напрямую и оставляет возможность дать вторую жизнь старым телефонам.
  Компромисс: больше вариантов прошивок и старых устройств для проверки; текущий
  прогон на API 36 не доказывает работу на API 26. DreamService сам по себе
  доступен с API 17, поэтому API 26 выбран не из-за его минимальной версии.
- **targetSdk 36 (Android 16)** — оставить для этого прототипа: он соответствует
  проверяемому устройству и доступному локальному SDK, включает актуальное для
  этого устройства поведение платформы. Это не выбранное значение для публикации.
- **compileSdk 36** — оставить вместе с targetSdk 36 в этой проверенной сборке.
  Цена: нельзя брать Compose UI 1.12.0, который требует compileSdk 37;
  используется стабильный совместимый BOM 2026.03.00.
- **compileSdk/targetSdk 37 (Android 17)** — следующий кандидат перед публичной
  версией. Потребуются SDK 37, повторный прогон двух хостов и проверка изменений
  поведения Android 17. Повышать targetSdk автоматически по номеру последнего
  SDK без такого прогона не предлагается.

## Альтернативы и условия принятия

minSdk 23–25 расширяет охват, но добавляет проверку старых прошивок и desugaring
для java.time; потребность в этом не подтверждена. Повышение minSdk до 29 или
выше сокращает матрицу, но отсекает часть потенциальных старых устройств;
текущие измерения не дают оснований для такого ограничения.

До окончательного решения: проверить выбранную нижнюю границу на устройстве
или эмуляторе (эмулятор не заменяет аппаратный прогон заставки), получить
результаты хотя бы ещё одной прошивки, отдельно подтвердить автоматический
запуск и блокировку, затем определить канал распространения и сверить его
актуальные требования. Не переносить предложения этого ADR в PRODUCT.md как
принятые решения без прямого подтверждения владельца.
