# Переходы автоматического StandBy 0.2.1

Утверждённое требование 2026-10-09: включённый режим действует всё время
подключённого питания. Полное отключение — только явный выключатель/уведомление.
Прежнее подавление до переподключения заменяется ожиданием следующего использования.

| Состояние / событие | Следующее состояние | Действие |
| --- | --- | --- |
| WAITING + питание + выключенный дисплей или keyguard | PENDING | Отложенный запуск; прежние 700 мс — стабилизация, не определение намерения |
| PENDING + пользователь разблокировал / отключил питание | WAITING | Отмена отложенного запуска |
| PENDING + дедлайн при сохранённых условиях | LAUNCHING | Новый уникальный token окна |
| LAUNCHING + SCREEN_ON от turnScreenOn | LAUNCHING | Не считать пробуждение использованием телефона |
| LAUNCHING + ранний onUserLeaveHint при собственном пробуждении HyperOS | LAUNCHING | Игнорировать: окно ещё не подтвердило показ |
| LAUNCHING + фокус совпадающего token | SHOWING | Подтверждение окна, отмена watchdog |
| SHOWING + USER_PRESENT / переход keyguard → unlocked при включённом экране | WAITING | Закрыть текущий показ, следующий SCREEN_OFF/keyguard снова доступен |
| SHOWING + Back/Home | WAIT_FOR_USE (USER_EXIT) | Закрыть текущий показ, ждать включённого разблокированного телефона |
| SHOWING/LAUNCHING + SCREEN_OFF текущего окна после подтверждённого interactive | WAIT_FOR_USE (DISPLAY_OFF) | Закрыть показ; дубли SCREEN_OFF, SCREEN_ON на keyguard и таймеры не будят экран |
| WAIT_FOR_USE + USER_PRESENT или interactive && !keyguard при отсутствии нашего окна | WAITING | Новый цикл использования подтверждён; следующая блокировка запускает StandBy |
| SHOWING + потеря фокуса/onStop/шторка/поворот | SHOWING | Это не намерение отключить показ; onStop не подавляет автозапуск |
| Событие окна со старым token | Без изменений | Старое окно не влияет на новую сессию |
| Любое + нет разрешения | BLOCKED (PERMISSION) | Закрыть/отменить показ; возврат разрешения и использование/явное включение разрешают новый цикл |
| LAUNCHING + отказ/истечение watchdog | WAIT_FOR_USE (LAUNCH_ERROR) | Без циклических повторов; повтор после использования/нового питания |
| Любое + выключатель/действие уведомления | DISABLED | Согласие false, служба и ресурсы освобождены; события использования не включают режим |
| Любое + отключение питания | WAITING (кроме DISABLED/BLOCKED) | Закрыть сразу, снять временную паузу; следующее подключение начинает новый цикл |

Без защищённой блокировки используется interactive + отсутствие собственного окна:
SCREEN_ON/USER_PRESENT, вызванные turnScreenOn активного StandBy, не признаются
использованием. Home/Back дают явный выход; следующий пользовательский экранный
цикл разрешает показ. Не используются временные эвристики для намерений пользователя.

Snapshot хранит причину паузы, а не постоянный запрет на всю зарядку. Старый
suppressed=true мигрирует в ожидание использования: не будить сразу погашенный
телефон, но снять паузу при следующем использовании без переподключения.
Восстановление процесса во время показа тоже ждёт использования либо нового питания.

Ранний дубликат SCREEN_OFF до первого включения дисплея и старый SCREEN_OFF,
доставленный при фактически включённом дисплее, не считаются нажатием питания.
Намерение определяется переходом экранных состояний, а не произвольным ожиданием.
Home передаётся отдельно как onUserLeaveHint и принимается только в SHOWING;
Back — явный Exit. Поздний hint старого token также не влияет на новое окно.

Окна завершаются через finish, а не удаление всей задачи: позднее завершение
старой Activity не удаляет задачу нового показа. Новый валидный onNewIntent
может включить экран после singleTask reuse; recreate той же сессии не будит его.

Стабилизация отключения 1500 мс из 0.2.0 удалена: подтверждённое отключение
сразу отменяет показ/запуск и временную паузу. Дубли текущего plugged не создают
нового подключения. Полный отказ пользователя и отсутствие разрешения не снимаются.
